## 评价设计

用户评价是结构化反馈：广告少/广告多，高清/一般/模糊。每个维度可选择不评价。同访客身份或账号、同来源保留一份当前评价，可修改或全部撤回；不是累计点击数。广告少与广告多互斥，画质选项互斥。

公开来源 API 返回各选项人数与总评价人数，不返回账号标识。评价入口仅放在播放器下方的视频详情区域，绑定当前来源；搜索结果和来源设置不提供评价按钮，只显示有票的 badge，例如“广告少 12”“高清 8”；总人数是参与身份数，不是 badge 数相加。管理员推荐继续独立显示。未登录用户也可评价：复用 Identity 访客会话（请求有效期 30 天，以 Identity 返回为准），同一浏览器访客身份可修改或撤回。登录后按账号计票，当前不自动合并访客票；清除 Cookie 或访客身份过期后无法再编辑旧访客票。

本次是标签式来源评价，不增加自由文本评论或回复线程；若未来增加文字讨论，按 Foundation `PublicCommentThread` 接入。没有另造线程、编辑器或评论身份系统。

持久化迁移 0011：组合主键保证一身份一来源一票，原子替换避免重复提交增加票数，撤回删除该评价。API 使用既有 HTTP Problem 合同，写入身份从已验证的账号或访客上下文取得，不能提交任意账号 ID。后台推荐与用户评价互不修改。

## 来源内部排序

搜索和发现结果只调整同一影片的来源顺序，不改变影片分组或相关性顺序。内部权重为高清 +10、广告少 +8、广告多 −8、模糊 −10，一般/未评价为 0；按各选项人数加总，降序排列。同分时推荐来源优先，之后保持原顺序。分数不返回公开 DTO，也不显示在页面，用户仅看到评价 badge 与人数。

排序在片源搜索缓存之后读取当前评价汇总，因此保存、修改、撤回后，下次查询即使用当前票数，不必重新抓取来源。评价读取失败遵循已有接口错误处理，不引入额外降级路径。
